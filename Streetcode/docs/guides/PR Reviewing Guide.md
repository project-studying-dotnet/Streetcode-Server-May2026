# Правила рев'ю PR

Backend PR знаходяться тут: https://github.com/project-studying-dotnet/Streetcode-Server-May2026/pulls. <br />
Frontend PR знаходяться тут: https://github.com/project-studying-dotnet/Streetcode-Client-May2026/pulls. <br />

Якщо виникнуть питання, звертайтесь до скрам-майстра.

## Обирання PR для рев'ю
1. Можете обирати будь-який PR. Пріоритетними є ті, які ще не мають достатньої кількості рев'ю.
   Рекомендую вибирати за SF (Short First) алгоритмом.
2. Перевірка PR із достатньою кількістю рев'ю за бажанням. Тим не менш, чим більше, тим краще.

## Рев'ю PR
1. Перевірити оформлення PR та issues відповідно до вимог в [Issue Closing Guide](./Issue%20Closing%20Guide.md).
2. Переглянути кожен доданий/змінений файл.
3. Якщо необхідно, потрібно запустити проєкт та перевірити чи працює він коректно.
4. Ви можете оновлювати PR, однак якщо виникне конфлікт, його повинен вирішити автор PR.
5. Ви не можете закривати чужі conversation, навіть якщо вони вже були виправлені. Це повинен робити його автор.

На основі перевірки робіть "change request", якщо бачите помилки або бажаєте уточнення від автора PR.
Для неважливих змін можна просто залишити коментар. Якщо все добре, робіть "approve".
Якщо PR вже має достатню кількість рев'ю, повідомте автора, що він може змерджити PR.

## Change request
Якщо ви зробили "change request", ви повинні надалі слідкувати за цим PR.
Ви це повинні робити до тих пір, поки автор PR не виправить всі помилки та не отримає "approve" від вас,
незалежно від того чи ви є черговим сьогодні чи ні. Не забудьте закрити ваші conversation, коли помилки будуть виправлені.
