# Duty Reviewers

## 1. Чергові

Для підтримки стабільного review-процесу команда може призначати чергових reviewers.

### Чергові відповідають за:

* підтримку актуального стану Pull Requests
* допомогу з оновленням гілок
* первинний review Pull Requests
* допомогу з merge conflicts
* контроль за тим, щоб PR не залишались без review протягом тривалого часу

---

## 2. Обов’язки reviewers (не тільки чергових)

### Reviewers можуть:

* виконувати первинну перевірку Pull Requests
* нагадувати авторам PR про необхідність виправлень
* координувати review-процес

---

## 3. Обмеження повноважень

### Reviewers не мають права:

* ігнорувати blocking issues
* скасовувати обґрунтовані запити на внесення змін `Request Changes` без попереднього обговорення
* блокувати merge через non-critical stylistic issues
* використовувати review-процес для особистих конфліктів або тиску на інших учасників команди

---

## 4. Очікувані терміни проведення review

### Чергові та reviewers повинні:

* реагувати на нові PR протягом усього часу свого чергування
* перевіряти PR після внесення requested changes
* не залишати Pull Requests у заблокованому стані без пояснення причин

---

## 5. Ротація чергових

Ротація чергових повинна бути регулярною, щоб:

* уникати концентрації review power в одних руках
* рівномірно розподіляти навантаження
* забезпечувати прозорість review-процесу
